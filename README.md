# Industrial Health Index (PdM)

Три метода детекции деградации подшипника — от классической физики (RMS) через
снижение размерности (PCA) до классификации (Random Forest) — честно сравненные на
независимой испытательной кампании и доведённые до практической рекомендации для
production.

## Проблема

В вибрационных данных промышленного оборудования ранние признаки износа маскируются
шумом, переходными режимами (пуск/остановка) и — при одновременной деградации
нескольких узлов — общим ростом фонового уровня вибрации. Стандартные пороговые методы
либо пропускают ранний износ, либо генерируют избыточные ложные тревоги.

## Датасет

[IMS Bearing Data Set](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/) — предоставлен Center for Intelligent Maintenance Systems (IMS), University of
Cincinnati, распространяется через NASA Prognostics Data Repository.

- 4 подшипника Rexnord ZA-2115 на одном валу, 2000 об/мин, радиальная нагрузка 6000
  фунтов, принудительная смазка
- Акселерометры PCB 353B33, частота дискретизации 20 кГц, 1с записи (20 480 точек)
  каждые 10 минут (первые ~43 файла Set 1 — каждые 5 минут)
- 3 теста «до отказа»: **Set 1** (2 156 файлов, 8 каналов — 2 датчика на подшипник, H и
  V), **Set 2** (984 файла, 4 канала — 1 датчик на подшипник), **Set 4** (6 324 файла,
  4 канала)
- Данные НЕ включены в репозиторий (`data/` в `.gitignore`) — скачать отдельно по
  ссылке выше и распаковать в `data/`

## Главный результат

Единственная объективная проверка — Set 4, кампания, ни разу не участвовавшая в
калибровке или обучении ни одного из трёх методов:

| Подшипник | Статус | RMS (физика) | PCA / Density-Grid | Random Forest |
| --- | --- | --- | --- | --- |
| B3 | реальный отказ | 1031.9ч | **994.2ч** (−37.7ч) | 1043.6ч |
| B4 | слабый сигнал, NASA-отказ не подтверждён | не обнаружен | **1014.4ч** (−36.3ч от RF) | 1050.7ч (без запаса) |

PCA / Density-Grid Health Index — простейший из трёх методов — оказался надёжнее
Random Forest на этой честной проверке. У B4 есть отдельная, более тонкая находка:
PCA также улавливает слабый, но физически подтверждённый ранний предвестник на 388.2ч
(за ~626 часов до отказа) — короткий всплеск, который полностью затухает на ~600 часов
и не является началом устойчивой прогрессии (см. «Методология», проверено количественно
и по времени, не принято на веру). Random Forest, даже после устранения всех найденных
багов, не даёт надёжного запаса времени на независимой кампании — вероятная причина в
6 обучающих траекториях отказа на 3 кампании, а не в оставшихся ошибках.

## Методология

Три последовательных подхода; каждый следующий закрывает конкретное ограничение
предыдущего.

| # | Подход | Метод | Что показал |
| --- | --- | --- | --- |
| 1 | Physics-based | RMS + адаптивный порог + экспоненциальная аппроксимация | Работает для локализованных дефектов; подвержен «ловушке медианы» при одновременной деградации нескольких узлов |
| 2 | Statistical | PCA / Density-Grid Health Index — PC1 по 7 признакам (RMS, kurtosis, skew, crest, energy, band_5_10k, spec_centroid), калибруется только на здоровом периоде каждого подшипника | Не требует обобщения между испытательными кампаниями — каждый подшипник калибруется независимо; поэтому надёжнее ML на held-out данных |
| 3 | ML | Random Forest, ~52 признака (базовые + rolling mean/std + градиент + Health Index), с инженерными фильтрами (маска приработки, порог уверенности, сглаживание) | Классификация состояния (Normal/Warning/Degradation/Critical); корректно ловит один из двух реальных отказов Set 4, но без полезного запаса времени по второму — вероятно, из-за малого числа обучающих траекторий |

### Найденные и исправленные баги (код-ревью, не просто отчёт)

- **Маппинг каналов Set 1.** Set 1 — единственный набор с 2 датчиками на подшипник (H и
  V). Функция извлечения нумерует колонки по порядку (`b1`…`b8`): `b1`=B1_H, `b2`=B1_V,
  `b3`=B2_H, `b4`=B2_V, `b5`=B3_H, `b6`=B3_V, `b7`=B4_H, `b8`=B4_V. Официальное описание
  NASA (Bearing 3 = Ch 5&6, Bearing 4 = Ch 7&8) подтверждает: `b3`/`b4`, ранее принятые
  за отказавшие подшипники, на деле были каналами здорового Bearing 2.
- **Утечка данных в PCA Health Index.** `StandardScaler`/`PCA` обучались на всём ряду
  целиком, включая уже случившуюся деградацию. Исправлено: `DensityGridMonitor`
  калибруется только на здоровом периоде (первые 50ч), встроен в основной пайплайн.
  Эффект утечки оказался разным по каналам (от часа до нескольких десятков) и
  непредсказуемым по знаку.
- **`dom_freq` = 0 для всей кампании Set 1.** Постоянное смещение сигнала (DC offset)
  доминировало нулевой бин FFT, `argmax` всегда возвращал 0 Гц — на 100% строк, включая
  период деградации. Исправлено на источнике (`features_engine.py`): DC-бин исключён из
  поиска максимума. Гипотеза «дело в `dom_freq`» как объяснение слабого обнаружения B4
  проверена дважды (удаление признака, затем полноценный фикс) и дважды отклонена —
  реальная причина в нехватке обучающих данных, не в этом баге.

## Практическая рекомендация для production

**Комбинация, а не замена одного метода другим:**

- **PCA / Density-Grid Health Index** — чувствительный ранний сигнал «watch this».
  Ловит даже слабые, прерывистые отклонения (как предвестник B4 на 388ч) — ценой того,
  что такой сигнал сам по себе не означает неминуемый отказ и может затухнуть.
  Подходит для мониторинга и планирования дополнительной диагностики.
- **Порог с требованием устойчивости или Random Forest с фильтрами** — консервативное
  подтверждение перед реальным вмешательством. Реагирует только на устойчивый, не
  затухающий сдвиг.

RNN для этой задачи не рекомендуется: если Random Forest (менее прожорливая до данных
модель) уже не обобщается надёжно между кампаниями на 6 траекториях, более сложная
архитектура на той же выборке скорее переобучится на шуме конкретной кампании, чем
выучит физику. Более здравая нейросетевая альтернатива — автоэнкодер, обученный только
на здоровых данных одного подшипника (та же идея, что в `DensityGridMonitor`, только
нелинейная версия) — не требует множества траекторий отказа для обучения.

## Известные ограничения

Спроектировано как честная фиксация того, что работает и что ещё нет, а не как отчёт
«всё готово».

1. **Гиперпараметры фильтров Random Forest** (порог уверенности 80%, приработка 100ч,
   сглаживание 12ч) не переподбирались под финальный признаковый набор.
2. **FPT для `Set2/B4`** (152.7ч, использован как метка для обучения) взят из самой
   первой, ещё leaky версии PCA — не пересчитан через `DensityGridMonitor`.
3. **«Доля времени выше порога»** — грубый диагностический инструмент: честно отличает
   устойчивый переход (100% у B3) от частичного сигнала (6.5% у B4), но сам по себе не
   различает «редкие метки одного нарастающего процесса» от «двух независимых событий».
   Разграничение «ранний предвестник → затухание → настоящая прогрессия» для B4
   основано на разборе по времени и физической интерпретации (подтверждённой сырой
   амплитудой), а не на строгом статистическом тесте — формализовать можно, например,
   через change-point detection или HMM с явным «предупреждающим» состоянием.
4. **Предсказание или описание.** Random Forest обучен на данных с уже известной меткой
   FPT — корректная методология, но означает, что качество на тренировочных данных не
   равно качеству предсказания. Настоящая проверка — `backtest()` на усечённых данных.
   Система выполняет раннюю классификацию состояния, а не точечный прогноз «часов до
   отказа».

## Структура репозитория

```
notebooks/
  industrial-health-index-pdm.ipynb   — весь анализ: EDA, 3 подхода, обучение, backtesting
  *_features.pkl                      — закэшированные признаки по датасетам (Set 1 / 2 / 4)
src/
  features_engine.py                  — извлечение признаков: библиотека + CLI
```

## Как запустить

```
git clone https://github.com/czeberyak/industrial-health-index-pdm.git
cd industrial-health-index-pdm
pip install -r requirements.txt

# Скачать IMS Bearing Data Set (см. раздел "Датасет") и распаковать в data/

# Извлечь и закэшировать признаки (по умолчанию кэш пишется рядом со скриптом):
python src/features_engine.py --data_path data/1st_test
python src/features_engine.py --data_path data/2nd_test
python src/features_engine.py --data_path data/4th_test

# Дальше — весь анализ в ноутбуке:
jupyter notebook notebooks/industrial-health-index-pdm.ipynb
```

Ноутбук проверялся через «Restart Kernel & Run All» — воспроизводится с нуля без
скрытых зависимостей от порядка выполнения ячеек.

## Планы

- Формализовать разделение transient/sustained аномалий (change-point detection или
  HMM) вместо порогового «% времени выше уровня».
- Автоэнкодер на здоровых данных как более чувствительная нелинейная альтернатива
  `DensityGridMonitor`.
- Расширенный backtesting: несколько подшипников и долей среза (70/80/90/97%) со
  сводной таблицей раннего предупреждения.
- Интерактивное демо (Streamlit) по аналогии с [RSM Tg/LSS Predictor](https://epoxy-structural-ep1.streamlit.app/) из проекта epoxy_structural_ep1.
